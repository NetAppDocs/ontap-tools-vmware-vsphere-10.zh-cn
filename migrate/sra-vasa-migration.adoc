= 迁移 VASA Provider 并在 ONTAP tools 中更新 SRA
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
使用此任务可将 VASA Provider 从 ONTAP tools for VMware vSphere 9.xx 迁移到 10.6，并更新 VMware Live Site Recovery 设备上的存储复制适配器 (SRA)。



[[migrate-the-vasa-provider]]
== 迁移 VASA 提供程序

.开始之前
确保部署了 ONTAP tools for VMware vSphere 10.6，并确保目标 vCenter Server 和存储后端已准备好进行迁移。

. 要在适用于 VMware vSphere 的现有 ONTAP tools 设备上启用 Derby 端口 1527，请启用 root 用户，通过 SSH 登录到 CLI，然后运行以下命令：
+
[listing]
----
iptables -I INPUT 1 -p tcp --dport 1527 -j ACCEPT
----
. 部署适用于 VMware vSphere 10.6 的 ONTAP tools for VMware vSphere 的 OVA。
. 添加要迁移到 ONTAP tools for VMware vSphere 10.6 的 vCenter Server 实例。有关详细信息，请参阅 link:../configure/add-vcenter.html["添加vCenter Server实例"]。
. 通过 ONTAP tools 插件的 vCenter Server API 在本地挂载存储后端。有关详细信息，请参见 link:../configure/add-storage-backend.html["使用 vSphere Client 界面添加存储后端"]。
. 获取访问令牌以验证 REST API 请求。请使用以下示例，并将变量替换为特定于您环境的值。
+
[source, curl]
----
curl --request POST \
  --location "https://$FQDN_IP_PORT/virtualization/api/v1/auth/vcenter-login" \
  --header "Content-Type: application/json" \
  --header "Accept: */*" \
  -d '{"username": "$MYUSER", "password": "$MYPASSWORD", "vcenter hostname": "$MYVCENTER"}'
----
+
复制并保存响应中返回的访问令牌。

. 从 Swagger 或 Postman 发出以下迁移 API 调用。
+
[listing]
----
curl -X POST `\https://xx.xx.xx.xx:8443/virtualization/api/v1/vcenters/{vcguid}/migration-jobs`
----
+
您可以通过此 URL 访问 Swagger： `\https://$FQDN_IP_PORT/` ， 例如： `\https://10.67.25.33:8443/` 。

+
[]

[[check-migration-status]]
=== 检查迁移状态

. 在Swagger中使用以下URI检查状态：
+
[listing]
----
curl `\https://xx.xx.xx.xxx:8443/virtualization/api/jobmanager/v2/jobs/<JobId>?includeSubJobsAndTasks=true`
----
+
使用上一步中从迁移作业返回的"id"值。作业完成后，在作业响应中查看迁移报告。





[[register-and-verify-the-migrated-vasa-provider]]
=== 注册并验证已迁移的 VASA Provider

. 使用ONTAP tools for VMware vSphere 的VASA 提供程序。有关说明，请参阅link:../configure/registration-process.html["注册VASA Provider"]。
. 验证 VASA Provider 注册：
+
.. 在 vSphere 客户端中，导航到 vCenter 服务器。
.. 选择 *Configure* > *Storage Providers*。
.. 确认上一步中注册的 VASA Provider 显示为在线。


. 请按照以下步骤停止ONTAP tools for VMware vSphere：
+
.. 在ONTAP工具 9.x 中，打开 Web 控制台。
.. 使用 `maint`凭据登录。
.. 进入 `1`选择“应用程序配置”菜单。
.. 进入 `5`停止 VASA Provider 和 SRA 服务。
.. 在 vSphere 客户端中，导航到 vCenter 服务器，然后选择*配置* > *存储提供程序*。
.. 选择适用于 ONTAP 工具 9.x 的离线 VASA Provider，然后选择*删除*。
+
旧的 VASA Provider 停止后，vCenter Server 将故障转移到 ONTAP tools for VMware vSphere。所有数据存储库和虚拟机均可访问，并由 ONTAP tools for VMware vSphere 提供服务。



. 迁移的 NFS 和 VMFS 数据存储区在数据存储区发现作业完成后出现在 ONTAP tools for VMware vSphere 10.6 中，这可能需要长达 30 分钟的时间。在概览页面上查看其可见性。

[[after-migration]]
== 迁移后

完成迁移并向 vCenter Server 注册 ONTAP tools 10.6 后，请执行以下步骤：

* 等待*发现*完成，系统会自动在所有主机上刷新证书。
* 等待数据存储区和虚拟机操作开始。等待时间取决于主机、数据存储和虚拟机的数量。如果您不等待，您可能会偶尔看到失败。


升级后、如果虚拟机的合规性状态已过时、请按照以下步骤重新应用存储策略：

. 转到数据存储并选择*摘要*>*虚拟机存储策略*。
. 系统显示*虚拟机存储策略合规性*下的合规性状态为*过时*。
. 选择存储虚拟机策略和相应的虚拟机。
. 选择*应用*。
. *虚拟机存储策略合规性*下的合规性状态显示为合规。

[[update-the-storage-replication-adapter-sra]]
== 更新存储复制适配器 (SRA)

.开始之前
在迁移 SRA 之前，请验证以下内容：

* 在恢复计划中，受保护站点是虚拟机当前运行的位置，而恢复站点是将恢复虚拟机的位置。
* 在 VMware Live Site Recovery 应用装置界面中，一个站点显示为受保护状态，另一个站点显示为恢复状态。
* 在恢复计划中，*CLEANUP* 和 *REPROTECT* 按钮已禁用，*TEST* 和 *RUN* 按钮保持启用状态。



NOTE: 如果故障转移已完成但重新保护处于挂起状态，请勿开始迁移。在继续迁移之前，请确保重新保护过程已完成。如果正在执行测试故障转移，请清除测试故障转移并开始迁移。

. 请按照以下步骤在VMware站点恢复中删除适用于VMware vSphere 9.xx的ONTAP工具SRA适配器：
. 转到 VMware Live Site Recovery 配置管理页面。
+
.. 转到*Storage Replication Adapter*部分。
.. 从省略号菜单中选择*重置配置*。
.. 从省略号菜单中选择*Delete*。


. 在保护站点和恢复站点上执行这些步骤。
+
.. link:../manage/enable-services.html["为VMware vSphere服务启用ONTAP工具"]
.. 使用 link:../protect/configure-on-srm-appliance.html["在VMware Live Site Recovery设备上配置SRA"] 中的步骤为 VMware vSphere 10.6 SRA 适配器配置 ONTAP tools。
.. 在 VMware Live Site Recovery 界面上，运行 *Discover Arrays* 和 *Discover Devices*。确认设备显示与迁移前相同。
